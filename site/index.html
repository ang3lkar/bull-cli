$ bull-cli

A terminal dashboard for BullMQ job queues. It works like bull-board, but runs in your shell. Point it at a Redis instance, then browse queues, jobs and job details, or retry, promote, pause and drain them, without opening a browser.

github npm usage keys config 
$ npm install -g @angelkar/bull-cli

Requires Node.js >= 20 and a reachable Redis with one or more BullMQ queues.

features

  • Zero config. It finds queues by running SCAN for bull:*:meta keys.
  • A queue list you can sort and filter, with totals across every queue and completed/failed jobs per minute.
  • Delayed, waiting, active, failed and completed jobs, with search. Pages fit the terminal's height.
  • Job schedulers (repeatable jobs): their schedule, next run and job template.
  • Job detail: failure reason, data, return value, stack trace and options. Copy the data JSON to the clipboard.
  • Retry one failed job or all of them, delete, promote and duplicate jobs. Pause, resume and drain queues.
  • Named connection profiles for switching between Redis instances.
  • bull-cli doctor explains an empty dashboard: wrong prefix, wrong DB, no connection.
  • --output=json and bull-cli retry for scripts, cron jobs and CI.
  • Refreshes every 3s. Runs in the alternate screen buffer, so your scrollback stays clean.

usage

bull-cli [options]
bull-cli doctor [options]
bull-cli retry --queue <name> (--dry-run | --yes) [--job-id <id> | --since <duration>]

  --redis <url>        Redis URL           # > REDIS_URL > profile > redis://localhost:6379
  --prefix <prefix>    BullMQ key prefix   # > BULLMQ_PREFIX > profile > bull
  --profile <name>     Connection profile from the config file
  --output <format>    Output mode         # json
  --queue <name>       Queue filter for --output=json; the queue to act on for retry
  --job-id <id>        retry: only this failed job
  --since <duration>   retry: only jobs that failed within this window (30s, 15m, 2h, 7d, 1w)
  --dry-run            retry: report what would be retried, change nothing
  --yes                retry: actually retry
  -h, --help
  -v, --version
$ bull-cli
$ bull-cli --redis redis://:secret@redis.internal:6379
$ bull-cli --prefix myapp
$ bull-cli --profile staging
$ bull-cli doctor
$ bull-cli --output=json --queue=email

retry from a script

bull-cli retry moves failed jobs back to waiting without opening the dashboard. It needs no TTY, refuses to run without --dry-run or --yes, prints a JSON summary, and exits 1 if anything failed.

$ bull-cli retry --queue email --dry-run           # how many would be retried?
$ bull-cli retry --queue email --yes               # every failed job
$ bull-cli retry --queue email --since 2h --yes    # failed in the last 2 hours
$ bull-cli retry --queue email --job-id 42 --yes   # just one job
{ "queue": "email", "dryRun": false, "filter": {}, "matched": 3, "retried": 3, "errored": 0, "errors": [] }

config

Optional. The CLI reads ./bull-cli.json, then ~/.config/bull-cli/config.json (or the same path under $XDG_CONFIG_HOME). Both files may use JSONC, and the project file overrides the user file key by key.

{
  // poll interval, ms (>= 250)
  "refreshIntervalMs": 3000,
  // per-refresh timeout, ms (>= 250); raise for remote/tunnelled Redis
  "refreshTimeoutMs": 5000,

  // pick one with --profile, or set a default
  "defaultProfile": "local",
  "profiles": {
    "local": { "redisUrl": "redis://localhost:6379" },
    "staging": { "redisUrl": "redis://staging.internal:6379", "prefix": "myapp" },
    // ${VAR} is read from the environment, so passwords stay out of the file
    "prod": { "redisUrl": "${PROD_REDIS_URL}", "prefix": "myapp" },
  },
}

--redis, --prefix, REDIS_URL and BULLMQ_PREFIX still win over a profile. bull-cli doctor shows where each value came from.
