$ bull-cli

A terminal dashboard for BullMQ job queues. It works like bull-board, but runs in your shell. Point it at a Redis instance, then browse queues, jobs and job details, or retry, promote, pause and drain them, without opening a browser.

github npm usage keys config 
$ npm install -g @angelkar/bull-cli

Requires Node.js >= 20 and a reachable Redis with one or more BullMQ queues.

features

  • Zero config. It finds queues by running SCAN for bull:*:meta keys.
  • Delayed, waiting, active, failed and completed jobs, with pagination and search.
  • Job detail: data, return value, stacktrace and options. Copy the data JSON to the clipboard.
  • Retry, delete, promote and duplicate jobs. Pause, resume and drain queues.
  • Refreshes every 3s. Runs in the alternate screen buffer, so your scrollback stays clean.
  • --output=json for scripts and CI.

usage

bull-cli [options]

  --redis <url>      Redis URL           # > REDIS_URL > redis://localhost:6379
  --prefix <prefix>  BullMQ key prefix   # > BULLMQ_PREFIX > bull
  --output <format>  Output mode         # json
  --queue <name>     Queue filter for --output=json
  -h, --help
  -v, --version
$ bull-cli
$ bull-cli --redis redis://:secret@redis.internal:6379
$ bull-cli --prefix myapp
$ bull-cli --output=json --queue=email

config

Optional. The CLI reads ./bull-cli.json, then ~/.config/bull-cli/config.json (or the same path under $XDG_CONFIG_HOME). Both files may use JSONC, and the project file overrides the user file key by key.

{
  // poll interval, ms (>= 250)
  "refreshIntervalMs": 3000,
  // per-refresh timeout, ms (>= 250); raise for remote/tunnelled Redis
  "refreshTimeoutMs": 5000,
}
